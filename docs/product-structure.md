# Cyber-Fox — структура продукта

Черновик для обсуждения. Облачная платформа управления компьютерными клубами.

## 1. Что строим

У платформы две жизни, и обе надо закладывать в архитектуру сразу:

- **Сегодня** — внутренняя система для собственных залов: считает время, берёт деньги,
  показывает выручку по каждому клубу.
- **Завтра** — продукт по подписке для чужих владельцев клубов.

Практическое следствие: одна общая база с обязательным разделением по клубам, единая точка
обновлений, самостоятельная регистрация клуба и привязка ПК по коду. То, что в локальной системе
делается вручную за пять минут, в SaaS должно делаться клиентом без нас — иначе продукт не
масштабируется дальше своей сети.

Отличие от Senet и SmartShell ищем не в списке функций (он будет примерно одинаковым), а в наличии
живых клубов для обкатки: видно, где администратор реально теряет время за смену.

## 2. Роли пользователей

| Роль | Где работает | Что делает |
|---|---|---|
| Владелец сети | веб-панель | Выручка и загрузка по всем клубам, сравнение залов, новые точки, назначение управляющих |
| Управляющий клубом | веб-панель | Один зал: тарифы, смены, сотрудники, бар, отчёт за день. Не видит соседние клубы |
| Администратор зала | кассовый экран | Главный пользователь. Посадить, пробить оплату, продлить, пересадить, продать товар, закрыть смену |
| Гость | экран ПК, приложение | Блокировка с таймером, вход по аккаунту, баланс и бонусы, позже — бронь с телефона |
| Владелец чужого клуба | будущий покупатель | Самостоятельная регистрация, перенос данных, подписка — без нашего участия |

## 3. Карта модулей

### Ядро — без этого клуб не работает

**Сессии и биллинг** — подробно в [billing.md](billing.md)
- Старт, пауза, продление, закрытие сессии
- Зоны зала (VIP, Стандарт, PS5), тарифы привязаны к зоне
- Пакеты часов и поминутные тарифы
- Автопереход на поминутку при исчерпании пакета, без разрыва сессии
- Игра в долг до лимита клуба (по умолчанию 100 ₸)
- Тарифы по времени суток
- Пересадка за другой ПК без потери времени

**Агент на игровом ПК** — офлайн-поведение в [offline.md](offline.md)
- Экран блокировки и вход гостя
- Таймер и остаток времени поверх игры
- Команды от сервера: старт, стоп, сообщение
- Защита от обхода
- Локальный таймер и очередь операций при обрыве связи

**Локальный узел на кассовой машине**
- Ставится тем же установщиком, что и агент; отдельно не настраивается
- Кэш конфигурации клуба и снимок балансов гостей
- Соединения с агентами зала по локальной сети
- Аварийный запуск сессий при недоступном облаке
- Очередь операций и досылка в облако после восстановления связи

**Касса и смены**
- Карта зала, приём денег (наличные, карта, онлайн)
- Пополнение баланса гостя
- Открытие и закрытие смены со сверкой кассы
- Журнал действий сотрудников

### Следом — то, ради чего купят вместо конкурента

**Гости и лояльность**
- Регистрация по телефону, история визитов
- Депозит, бонусные баллы, уровни
- Абонементы и пакеты часов
- Возврат «спящих» гостей

**Бар и товары**
- Каталог и остатки на складе
- Заказ прямо с игрового ПК
- Себестоимость и маржа в отчёте

**Бронирование**
- Карта зала с занятостью
- Бронь командой на несколько мест
- Автоотмена и предоплата брони

**Отчёты по сети**
- Выручка и загрузка по залам
- Прибыльность каждого ПК
- Часы пик и мёртвые часы
- Выработка по сменам сотрудников

### Позже — продаётся как расширение

**Управление парком ПК**
- Включение по сети (Wake-on-LAN), перезагрузка
- Раскатка обновлений и игр
- Общие аккаунты лаунчеров
- Сигнал о неисправном железе

**Подписки и тенанты**
- Регистрация нового клуба
- Тарифы платформы и счета
- Лимиты по числу ПК
- Перенос данных с Senet и SmartShell

## 4. Архитектура

```
        КЛУБ (локальная сеть)                    ОБЛАКО
   ┌──────────────────────────┐        ┌──────────────────────────┐
   │  Игровой ПК · агент      │        │   Сервер платформы       │
   │  блокировка, таймер      │───────▶│   сессии · биллинг       │
   │  × N машин в зале        │ команды│   права доступа          │
   └──────────────────────────┘ статус └───────────┬──────────────┘
                                                   │
   ┌──────────────────────────┐        ┌───────────▼──────────────┐
   │  Кассовый экран          │───────▶│   База данных            │
   │  браузер администратора  │кассовые│   все клубы, разделены   │
   └──────────────────────────┘операции└───────────┬──────────────┘
                                                   │
                                        ┌──────────▼──────────────┐
                                        │  Веб-панель владельца   │
                                        │  отчёты по всей сети    │
                                        └─────────────────────────┘
```

| Часть | Что это | Где работает |
|---|---|---|
| Агент | Программа блокировки на игровом ПК | Windows, каждая машина |
| Сервер | Логика сессий, деньги, права доступа | Облако, один на всех |
| Панель | Кассовый экран и отчёты | Браузер |
| Приложение | Бронь и баланс для гостя | Телефон, позже |

При обрыве интернета агент доигрывает оплаченную сессию по локальному таймеру и досылает данные
после восстановления связи — зал не останавливается.

## 5. Модель данных

Каждая запись принадлежит клубу (`clubId`) — это разделение позже пустит в систему чужих
владельцев без переписывания.

```
Club            название, город, часовой пояс, подписка, лимиты долга
Zone            VIP / Стандарт / PS5, поминутный тариф по умолчанию
Computer        номер, зона, статус, код привязки
Tariff          зона, вид (пакет или поминутный), цена, время суток
Guest           телефон, имя, баланс, бонусы
Session         ПК, зона, гость, начало, конец, итоговая сумма
SessionSegment  отрезок сессии: тариф, минуты, сумма, причина закрытия
Payment         сумма, способ, смена, кассир, привязка к сессии
Shift           сотрудник, открытие, закрытие, сверка кассы
Staff           роль, доступ, привязка к клубу, журнал действий
```

Сессия хранится как цепочка отрезков: пакет закончился — отрезок закрывается, открывается новый по
поминутному тарифу, сессия продолжается. Подробно в [billing.md](billing.md).

## 6. Основной сценарий

Повторяется сотни раз за смену; всё остальное существует, чтобы он проходил без заминок.

1. **Гость** — подходит к стойке, просит место на два часа
2. **Админ** — видит карту зала, свободные подсвечены; выбирает ПК №14
3. **Админ** — выбирает тариф, принимает оплату, жмёт «Начать»
4. **Система** — записывает сессию, снимает деньги, шлёт команду на ПК №14
5. **Агент** — снимает блокировку, показывает таймер: осталось 2:00
6. **Агент** — за 10 минут до конца предупреждает поверх игры
7. **Гость** — просит продлить; админ добавляет час одной кнопкой, игра не прерывается
8. **Система** — по истечении времени блокирует экран, освобождает место на карте
9. **Владелец** — вечером видит выручку по ПК №14 и загрузку зала

## 7. Дорожная карта

Этапы строго последовательны: следующий имеет смысл, только когда предыдущий работает в живом зале.
Сроки — ориентир для одного разработчика на полную занятость.

**Этап 01 — Один клуб, одна смена** (~6 недель)
Сервер, база, вход для сотрудников, карта зала, тарифы, старт и стоп сессии, агент с блокировкой и
таймером. Оплата наличными, один отчёт за смену.
Итог: один зал полностью работает на Cyber-Fox.

**Этап 02 — Деньги и гости всерьёз** (~4 недели)
База гостей, депозит и бонусы, безналичная оплата, пакеты часов, продажа товаров, закрытие смены со
сверкой кассы.
Итог: система заменяет тетрадь и кассу целиком.

**Этап 03 — Вся сеть в одном окне** (~4 недели)
Подключение остальных клубов, права управляющих, сводные отчёты по сети, устойчивость к обрывам
связи.
Итог: продукт доказал, что держит несколько залов.

**Этап 04 — Готовность к чужому клубу** (~6 недель)
Самостоятельная регистрация, установщик агента, подписка и счета, перенос данных со старой системы,
документация.
Итог: первый внешний клуб подключается без выезда на место.

**Этап 05 — То, за что доплачивают** (дальше)
Бронирование с телефона, приложение для гостя, удалённое управление парком ПК, турниры, интеграция
с кассовым оборудованием.
Итог: расширения, продаваемые сверх базовой подписки.

## 8. Что решаем до первой строчки кода

Эти решения дороже всего менять потом — они определяют структуру базы и поведение системы в зале.

**Тарифная модель — решено.** Пакеты и поминутная тарификация, зоны зала, автопереход на поминутку
при исчерпании пакета, игра в долг до 100 ₸. Спецификация: [billing.md](billing.md).

**Поведение без интернета — решено.** Оплаченные сессии идут по локальному таймеру, новые
запускаются в аварийном режиме, данные досылаются после восстановления связи. Спецификация:
[offline.md](offline.md).

**Вход гостя.** По личному аккаунту или администратор просто открывает машину? Аккаунты нужны для
бонусов и брони, но замедляют посадку. Возможен смешанный вариант.

**Касса и фискализация.** Нужна ли работа с кассовым оборудованием на первом этапе? Требования
различаются по странам — может стать отдельным этапом, а не частью ядра.

**Размер полигона.** Сколько клубов и сколько машин в самом большом зале? Число одновременных
соединений определяет требования к серверу и стоимость облака.

**Что раздражает сейчас.** Чем пользуются клубы сегодня и что больше всего мешает? Конкретная боль
администратора станет первым преимуществом при продаже чужим клубам.
