# Установка на Windows

Пилот на своём ноутбуке или на машине в зале: сервер стоит внутри клуба,
игровые ПК подключаются к нему по локальной сети. Домен и HTTPS не нужны.

Для боевой установки на облачный сервер с доменом — [deploy.md](deploy.md).

## 1. Что понадобится

| Что | Откуда |
|---|---|
| Docker Desktop | docker.com/products/docker-desktop — нужен WSL2 и включённая виртуализация в BIOS |
| Git | git-scm.com — чтобы забрать код и потом обновляться |
| Установщик агента | Собирается из этого репозитория или берётся готовым файлом |

Ноутбуку хватит 8 ГБ памяти. Если Docker Desktop не ставится, почти всегда
причина одна — в BIOS выключена виртуализация (Intel VT-x или AMD-V).

## 2. Сервер

В PowerShell:

```powershell
git clone <репозиторий> cyber-fox
cd cyber-fox
Copy-Item deploy\env.example .env
notepad .env
```

Для пилота в локальной сети заполните только это:

```
POSTGRES_PASSWORD=придумайте-длинный-пароль
JWT_SECRET=придумайте-другой-длинный-секрет
TZ=Asia/Almaty
```

`CYBERFOX_DOMAIN` и `ALLOWED_ORIGINS` оставьте как есть — в локальном режиме
они не используются.

Запуск — двойным щелчком по `deploy\windows\start.cmd` либо командой:

```powershell
docker compose -f docker-compose.yml -f deploy\lan.yml up -d
```

Первый запуск занимает несколько минут: собираются образы. Скрипт покажет
адрес вида `http://192.168.1.50:8080` — по нему открывается кассовый экран,
его же вводят на игровых машинах.

**Узнать адрес позже:** `ipconfig`, строка «IPv4-адрес».

### Чтобы адрес не менялся

По умолчанию роутер выдаёт ноутбуку адрес на время, и после перезагрузки он
может смениться — тогда все агенты разом потеряют сервер. Перед пилотом
закрепите за этой машиной постоянный адрес в настройках роутера (привязка по
MAC) или задайте статический IP в свойствах сетевого адаптера.

### Брандмауэр

При первом запуске Windows спросит про доступ к сети — разрешите для частных
сетей. Если игровые машины не видят сервер, откройте порт вручную (PowerShell
от администратора):

```powershell
New-NetFirewallRule -DisplayName "Cyber-Fox" -Direction Inbound -LocalPort 8080 -Protocol TCP -Action Allow
```

## 3. Клуб

Откройте `http://ваш-адрес:8080`, нажмите «Зарегистрировать клуб». Дальше —
как в [deploy.md](deploy.md), раздел 4: зоны, машины, тарифы, перенос гостей
из прежней системы.

## 4. Агент на игровых машинах

### Если установщик прислан частями

Положите `CyberFoxAgentSetup.part00`, `.part01`, `.part02` в одну папку с
`deploy\windows\join-installer.cmd` и запустите его. Он склеит файл и покажет
контрольную сумму — сверьте её.

Вручную то же самое:

```powershell
cmd /c copy /b CyberFoxAgentSetup.part00+CyberFoxAgentSetup.part01+CyberFoxAgentSetup.part02 "Cyber-Fox Agent Setup.exe"
certutil -hashfile "Cyber-Fox Agent Setup.exe" SHA256
```

### Если собираете сами

```powershell
npm install -g pnpm
pnpm install
pnpm --filter @cyberfox/agent pack:win
```

Готовый файл — в `apps\agent\release`.

### На каждой машине

1. Запустить установщик. Windows покажет предупреждение SmartScreen —
   «Подробнее» → «Выполнить в любом случае». Оно будет на каждой машине, пока
   установщик не подписан сертификатом.
2. Агент запустится сам и спросит адрес сервера и код привязки:
   - адрес — `192.168.1.50:8080` (схему `http://` можно не писать, для адресов
     локальной сети она подставляется сама);
   - код — из админки, экран «Подключение», рядом с названием ПК. Каждый код
     подходит только к одной машине.
3. Убедиться, что машина появилась в карте зала как «на связи».
4. Один раз, от имени администратора, поставить сторожа:
   ```powershell
   powershell -ExecutionPolicy Bypass -File deploy\agent\install-watchdog.ps1
   ```

## 5. Каждый день

- **Включение:** запустите Docker Desktop, затем `start.cmd`. Чтобы не делать
  этого руками, включите в Docker Desktop автозапуск при входе в систему, а
  в настройках compose всё уже помечено `restart: unless-stopped`.
- **Выключение:** `stop.cmd`. База и бэкапы остаются на месте.
- **Бэкапы** складываются в папку `backups` раз в сутки. Раз в неделю
  копируйте свежий файл на флешку или в облако: бэкап на том же ноутбуке не
  спасает от потери ноутбука.
- **Обновление:**
  ```powershell
  git pull
  docker compose -f docker-compose.yml -f deploy\lan.yml up -d --build
  ```

## 6. Чего в этом режиме нет

**HTTPS.** Сертификат на адрес вида `192.168.1.50` не выдаётся, поэтому связь
внутри клуба идёт открытым текстом. Данные не покидают локальную сеть, но от
того, кто уже в неё попал, защиты нет. Для боевой работы — домен и обычный
`docker compose up` с автоматическим HTTPS.

**Ноутбук как сервер — только на пилот.** Закрытая крышка, спящий режим,
случайно выключенный Wi-Fi — и зал остаётся без сервера. Оплаченные сессии
доиграют, новые не начнутся. Отключите спящий режим на время пилота, а после
переносите сервер в облако или на отдельную машину, которая не выключается.

**Онлайн-оплата.** В локальном режиме провайдер не сможет прислать
подтверждение: у него нет доступа внутрь вашей сети. Кассир принимает
наличные и отмечает переводы вручную.
