# Установка с нуля: от коробки до первого гостя

Одна инструкция на весь путь. Написана для клуба, где игровые машины грузятся
по сети с общего образа (CCBoot) — так стоит большинство залов.

Если машины с обычными дисками, отличается только раздел 7 — там смотрите
[install-windows.md](install-windows.md).

Подробности по каждому шагу — в отдельных документах, ссылки по ходу. Здесь
только то, что делаешь руками, по порядку.

## 0. Что где будет стоять

В клубе будет две серверные машины. Их путают чаще всего, поэтому сразу:

```
   ┌─────────────────────┐         ┌──────────────────────┐
   │  Сервер загрузки    │         │  Мини-ПК Cyber-Fox   │
   │  (CCBoot, уже есть) │         │  (покупаем)          │
   │                     │         │                      │
   │  Windows и игры     │         │  База, деньги, касса │
   │  на быстрых SSD     │         │  Веб-экран админа    │
   └──────────┬──────────┘         └──────────┬───────────┘
              │ 10 Гбит                       │ обычный гигабит
              │ (гигабайты игр)               │ (байты команд)
        ┌─────┴───────────────────────────────┴─────┐
        │        Игровые ПК зала, без дисков        │
        │   Внутри образа стоит Cyber-Fox Agent     │
        └───────────────────────────────────────────┘
```

Две программы, и они ставятся в разные места:

| Программа | Куда ставится | Что делает |
|---|---|---|
| **Сервер Cyber-Fox** | на мини-ПК | считает минуты и деньги, показывает кассовый экран |
| **Cyber-Fox Agent** | внутрь образа CCBoot | блокирует игровой ПК, показывает экран гостю |

Агент на мини-ПК не ставится. Сервер в образ не кладётся.

Cyber-Fox игры не раздаёт и файлы не гоняет — этим и дальше занимается CCBoot.
По сети от агента к серверу идут только короткие команды: «машина на связи»,
«гость сел», «минута прошла».

## 1. Что купить

**Мини-ПК.** Один, тысяч за 60–80 тг.

| Что | Сколько хватит |
|---|---|
| Процессор | 2 ядра |
| Память | 4 ГБ |
| Диск | 40 ГБ SSD |
| Сеть | гигабит, проводом |
| Система | Windows 10/11 |

Это очень скромные требования: сервер Cyber-Fox — это база и веб-приложение, а
не файловый поток. Нагрузка от сорока машин на нём почти незаметна.

**Почему отдельная коробка, а не на сервере загрузки.** Сервер загрузки
перезагружают каждый раз, когда правят образ. Стоял бы Cyber-Fox там же —
вместе с образом падала бы касса, посреди смены, с гостями в зале.

**Почему не облако.** Можно и в облако, но тогда обрыв интернета у провайдера
означает «новых гостей посадить не можем». Зал работает сменами по двенадцать
часов, и это прямая потеря выручки. Мини-ПК в клубе убирает провайдера из
критического пути. Переехать в облако потом — это один дамп базы и тот же
запуск на VPS, решение ничего не запирает.

## 2. Готовим мини-ПК

Всё в этом разделе делается один раз.

### 2.1 Программы

Поставить два бесплатных пакета:

1. **Docker Desktop** — docker.com/products/docker-desktop
2. **Git** — git-scm.com

Docker может не поставиться. Причина почти всегда одна: в BIOS выключена
виртуализация (называется `Intel VT-x` или `AMD-V`). Включить и повторить.

Дождаться в Docker Desktop надписи **Engine running**.

### 2.2 Автозапуск и сон

- В Docker Desktop: **Settings** → **General** → включить **Start Docker Desktop
  when you sign in**
- В Windows: **Параметры** → **Система** → **Питание** → спящий режим
  **Никогда**

Уснувший мини-ПК — это зал, который разом потерял сервер.

### 2.3 Постоянный адрес

Зайти в роутер и закрепить за мини-ПК постоянный адрес (привязка по MAC).

Это не формальность. Адрес мини-ПК попадёт внутрь образа CCBoot. Сменится
адрес — все сорок машин перестанут видеть сервер, и лечится это правкой образа
и перезагрузкой зала.

## 3. Ставим сервер

В PowerShell на мини-ПК:

```powershell
git clone https://github.com/aliaskarov007/cyber-Fox.git cyber-fox
cd cyber-fox
Copy-Item deploy\env.example .env
notepad .env
```

В блокноте заполнить три строки, остальное не трогать:

```
POSTGRES_PASSWORD=длинный-пароль-который-никто-не-угадает
JWT_SECRET=другой-длинный-секрет-не-такой-же
TZ=Asia/Almaty
```

Пароли должны быть разными и длинными. Придумать их можно прямо в PowerShell:

```powershell
-join ((48..57) + (97..122) | Get-Random -Count 40 | ForEach-Object {[char]$_})
```

`CYBERFOX_DOMAIN` и `ALLOWED_ORIGINS` оставить как есть — в локальной сети
клуба они не используются.

Запуск — двойным щелчком по `deploy\windows\start.cmd`.

Первый раз собирается несколько минут: скачиваются образы и собирается сервер.
Дальше запуск занимает секунды.

Скрипт напечатает адрес вида `http://192.168.1.50:8080`. **Записать его** — он
понадобится дальше и попадёт в образ.

Когда Windows спросит про доступ к сети — разрешить **для частных сетей**. Если
машины зала потом не увидят сервер, открыть порт вручную, в PowerShell от
администратора:

```powershell
New-NetFirewallRule -DisplayName "Cyber-Fox" -Direction Inbound -LocalPort 8080 -Protocol TCP -Action Allow
```

Проверка: открыть записанный адрес в браузере на мини-ПК, потом на любом другом
компьютере в той же сети. Оба раза должен открыться экран входа.

## 4. Заводим клуб

В браузере по тому же адресу:

1. **«Зарегистрировать клуб»** — заводится владелец, клуб и пробный период
2. **Настройки → Зоны** — хотя бы одна зона. Машины заводить не нужно, они
   появятся сами при первой загрузке
3. **Тарифы** — поминутные и пакеты, отдельно по зонам

Про цены: заведите ровно те же, что в прежней системе. Пилот проверяет
систему, а не новый прайс — иначе непонятно, что именно пошло не так.

Если переносите гостей из Senet, SmartShell или Excel: **Подключение** →
**Перенос из прежней системы**. Загружать можно повторно, гости сопоставляются
по телефону, дубли не появятся. После переноса сверьте число гостей и **сумму
балансов** — расхождение здесь это чужие деньги, и заметить его нужно сейчас, а
не в конце месяца.

## 5. Берём ключ клуба

Админка → **Подключение** → **«Показать ключ клуба»**.

Там будет готовое содержимое файла:

```json
{
  "serverUrl": "http://192.168.1.50:8080",
  "enrollmentKey": "0ad59b44-…"
}
```

Скопировать, сохранить в файл с именем **`cyberfox.json`**. Он поедет в образ.

Что это за ключ: он пускает машину в клуб как игровой ПК. Денег не даёт и кассу
не открывает. Но образ всё равно держите там, куда у гостей нет доступа.

Отдельные коды на каждую машину в бездисковом зале не нужны — один ключ на весь
клуб, а машины различаются по MAC-адресу сетевой карты.

## 6. Берём установщик агента

Файл называется **`Cyber-Fox Agent Setup 0.1.0.exe`**, весит около 78 МБ.

Его нет в репозитории — git не место для восьмидесяти мегабайт. Два пути:

**Скачать.** Прямая ссылка, одинаковая для всех выпусков:

```
https://github.com/aliaskarov007/cyber-Fox/releases/latest/download/CyberFoxAgentSetup.exe
```

Она же стоит кнопкой в кассе, раздел «Подключение». Файл собирается на настоящей
Windows проверкой на каждый выпуск.

**Взять готовый файл у кого-то.** Тогда обязательно сверьте контрольную сумму
после копирования:

```powershell
certutil -hashfile "Cyber-Fox Agent Setup 0.1.0.exe" SHA256
```

**Собрать самому.** Нужен Node.js 20+:

```powershell
npm install -g pnpm
pnpm install
pnpm --filter @cyberfox/agent pack:win
```

Готовый файл появится в `apps\agent\release`. Собирать можно и на macOS, и на
Linux — сборщик сам добавит недостающее.

## 7. Кладём агента в образ

Здесь всё делается **один раз для всего зала**, а не сорок раз.

Перед началом: в CCBoot у каждого клиента должно быть своё имя (`PC-01`,
`PC-02`). Cyber-Fox возьмёт эти имена как названия машин в карте зала, и
администратор увидит на экране то же, что написано на корпусе. Проверить:
**Client Manager** → колонка *Computer Name*.

Порядок:

1. В CCBoot перевести образ в режим записи: **Image Manager** → нужный образ →
   *Enable Write* (в некоторых версиях — загрузить назначенный клиент как
   Super Client)
2. Загрузить **одну** машину с этого образа
3. Установить на неё агента обычным установщиком. Windows покажет красное окно
   SmartScreen — **«Подробнее»** → **«Выполнить в любом случае»**. Так будет,
   пока установщик не подписан сертификатом
4. Положить файл `cyberfox.json` рядом с программой:
   `C:\Program Files\Cyber-Fox Agent\cyberfox.json`
5. Поставить сторожа, в PowerShell от имени администратора:
   ```powershell
   powershell -ExecutionPolicy Bypass -File install-watchdog.ps1
   ```
   Сторож раз в минуту поднимает агента, если процесс сняли через диспетчер
   задач
6. Проверить прямо на этой машине: агент подключился, машина появилась в карте
   зала под своим именем
7. Выключить машину, в CCBoot сохранить образ и вернуть режим только чтения

Ничего настраивать в кэше записи не нужно: агент намеренно не хранит на клиенте
ничего, что должно пережить перезагрузку.

## 8. Раскатываем на зал

Перезагрузить остальные машины.

Каждая при первой загрузке появится в карте зала сама, под своим именем из
Windows. Все новые машины попадают в первую зону — расставить их по зонам можно
потом, когда все будут на связи.

Проверка: в админке столько машин «на связи», сколько включено в зале.

## 9. Что проверить до гостей

Сделайте это сами, на пустом зале. Найденное здесь стоит несравнимо дешевле
найденного при очереди на стойке.

**Бездисковая схема — отдельно:**

- [ ] Перезагрузить машину — агент поднялся сам, настройку не спрашивает
- [ ] Перезагрузить **дважды подряд** — в зале не появилось машины-двойника
- [ ] Две машины одновременно — каждая под своим именем, не путаются
- [ ] Начать сессию, перезагрузить машину посреди игры — игра продолжается с
      тем же остатком
- [ ] Выключить машину из розетки на минуту — уходит со связи, сессия
      закрывается сама через полчаса молчания

Пункт про двойника главный: если после перезагрузки машин стало больше, значит
агент цепляется за нестабильный сетевой адаптер. Чинить до пилота, не после.

**Деньги и смена:**

| Проверка | Что должно произойти |
|---|---|
| Открыть смену, посадить гостя со стойки | Машина разблокировалась, таймер пошёл |
| Гость входит сам по телефону и PIN | То же самое, без администратора |
| Дать закончиться пакету минут | Игра **не прерывается**, включается поминутный тариф |
| Довести баланс до нуля | Игра идёт в долг до лимита клуба, потом блокировка |
| Пересадить гостя в другую зону | Время не потерялось, остаток пакета остался за прежней зоной |
| Пополнить наличными и онлайн | Обе суммы попали в кассу смены |
| Выдернуть интернет на 10 минут | Оплаченная игра идёт дальше |
| Закрыть смену | Сверка кассы сходится с ящиком |

**Попытки обхода** — гости пробуют это в первую же неделю:

- [ ] Диспетчер задач: снять процесс агента — вернулся в течение минуты
- [ ] Alt+F4, Alt+Tab, клавиша Windows — блокировка не уходит

Полный лист дня установки — [pilot-checklist.md](pilot-checklist.md).

## 10. Каждый день

- **Включение.** Docker Desktop стартует сам, контейнеры тоже. Если
  запускаете руками — `start.cmd`
- **Выключение.** `stop.cmd`. База и бэкапы остаются на месте
- **Бэкап** делается сам, раз в сутки, в папку `backups`, и уезжает за пределы
  клуба, если настроено внешнее хранилище — см. ниже
- **Проверьте восстановление один раз**, до пилота, а не в день аварии:
  ```powershell
  docker compose exec -T db psql -U cyberfox -d cyberfox
  ```
  (подать на вход разжатый файл из `backups`)

### Копия за пределами клуба

Бэкап на том же мини-ПК не спасает от потери мини-ПК: сгоревший блок питания
уносит вместе с машиной остатки на счетах гостей, а это чужие деньги.

Настраивается один раз, ключ шифрования делается на вашем компьютере, а не в
клубе:

```powershell
age-keygen -o cyberfox-backup.key     # закрытый ключ хранить ВНЕ клуба
ssh-keygen -t ed25519 -f offsite-key -N ""
```

Открытую часть SSH-ключа добавьте в хранилище (Hetzner Storage Box или любой
сервер с SSH), файл `offsite-key` положите на мини-ПК, а в `.env` заполните:

```
BACKUP_AGE_RECIPIENT=age1...      # строка Public key из cyberfox-backup.key
OFFSITE_HOST=u123456.your-storagebox.de
OFFSITE_USER=u123456-sub1
OFFSITE_KEY=./deploy/backup/offsite-key
```

Копия шифруется до отправки: на чужом диске лежит то, что без закрытого ключа не
прочитать. Обратная сторона — **потеряете закрытый ключ, потеряете все копии**.
Держите его там же, где документы клуба, а не на мини-ПК.

Без `BACKUP_AGE_RECIPIENT` отправка не происходит вовсе: увозить имена, телефоны
и балансы гостей на чужой диск открытым текстом нельзя. Неудачная отправка
пишется в журнал словами `КОПИЯ НЕ УЕХАЛА` — молчание тут опаснее ошибки.

## 11. Обновления

**Сервер** — между сменами:

```powershell
git pull
docker compose -f docker-compose.yml -f deploy\lan.yml up -d --build
```

Миграции базы применяются при старте сами.

**Агент на машинах с дисками обновляется сам.** Раз в шесть часов он проверяет
выпуски и ставит новую версию молча — но только когда машина свободна:
перезапуск посреди оплаченной игры гость воспримет как поломку. Ходить по залу
не нужно.

**Агент в бездисковом зале сам не обновляется, и это намеренно.** Он лежит
внутри образа, а записанное поверх исчезает при перезагрузке: обновление
скачалось бы, поставилось, пропало при ребуте и скачалось снова — сорок закачек
по восемьдесят мегабайт каждую загрузку зала. Такие машины обновляются правкой
образа: образ в режим записи → одна машина → установщик поверх → сохранить
образ → перезагрузить зал.

**Файл `cyberfox.json` при обновлении пропадает — положите его заново.** Новая
версия ставится не поверх старой: сначала отрабатывает деинсталлятор, а он
удаляет папку программы целиком, вместе со всем, что там лежит. Забыть об этом
означает зал, который после перезагрузки просит настроить каждую машину руками.

Порядок обновления агента поэтому такой:

1. Установщик поверх
2. Положить `cyberfox.json` обратно в `C:\Program Files\Cyber-Fox Agent\`
3. Проверить на этой же машине, что агент подключился
4. Сохранить образ

Делать это между сменами: перезагрузка зала посреди работы прервёт игру, а
несохранённое у гостей пропадёт вместе с кэшем записи.

## 12. Чего пока нет — знать заранее

Честный список. Ничто из этого не мешает работать в своём зале, но каждое
всплывёт при продаже чужому клубу.

**Установщик не подписан.** Красное окно SmartScreen при установке. В
бездисковом зале это один раз на образ, на машинах с дисками — на каждой.

Лечится сертификатом подписи кода: OV стоит примерно 200–400 долларов в год и
набирает доверие Windows постепенно, EV дороже и работает сразу. Сборка к этому
готова — подпись включится сама, как только сертификат и пароль к нему попадут
в секреты репозитория под именами `WINDOWS_CERT_BASE64` и
`WINDOWS_CERT_PASSWORD`. Переделывать ничего не придётся.

**У агента стандартная иконка.** Мелочь, которая на чужом ПК читается как
поделка.

**Блокировка держит обычного гостя, а не подготовленного.** На время оплаченной
сессии агент закрывает проводнику чужие диски, «Выполнить», панель управления,
regedit и командную строку, а после сессии снимает запреты обратно. Диски `C` и
`D` остаются видимыми, чтобы гость доходил до своих сохранений и скриншотов;
изменить список можно переменной `CYBERFOX_VISIBLE_DRIVES` в образе.

Но это запреты в ветке реестра самого гостя, и тот, кто дошёл до безопасного
режима, второй учётной записи Windows или загрузки с флешки, снимет их сам.
Настоящее решение: пароль на BIOS и запрет загрузки с внешних носителей.
Для бездискового зала это делается один раз на партии машин.

**Новых гостей без интернета посадить нельзя.** Оплаченная игра доигрывается,
но новая сессия не запускается. Если связь падает часто — 4G-модем запасным
каналом. Подробности: [offline.md](offline.md).

**Онлайн-оплата требует договора с провайдером.** Сейчас кассир отмечает
переводы вручную.

**Минуты теряются при перезагрузке во время обрыва связи.** Журнал отыгранного
лежит в кэше записи и стирается вместе с ним. Система при сбое скорее
недосчитает, чем возьмёт с гостя лишнее.

**HTTPS внутри клуба нет.** Связь между машинами и сервером идёт открытым
текстом по локальной сети. От того, кто уже внутри сети, защиты нет.

## Если что-то не работает

| Что видно | Куда смотреть |
|---|---|
| Docker не ставится | Виртуализация в BIOS (`Intel VT-x` / `AMD-V`) |
| `start.cmd` пишет «Docker не запущен» | Открыть Docker Desktop, дождаться «Engine running» |
| Касса не открывается с другой машины | Брандмауэр, правило на порт 8080 |
| Машины зала не появляются | Адрес в `cyberfox.json` не совпадает с адресом мини-ПК |
| Машины появляются двойниками | Нестабильный сетевой адаптер, см. раздел 9 |
| Сервер не поднялся | `docker compose logs server` |
