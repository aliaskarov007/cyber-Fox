# Установка на облачный сервер

Сервер в интернете, свой домен, HTTPS. Так ставят, когда клубов несколько или
нужен доступ к отчётам из дома.

Сервер прямо в клубе, без домена — [setup.md](setup.md). Разница важная: при
облачном сервере обрыв интернета в клубе означает, что новые сессии не
запускаются (оплаченные доигрывают).

## 1. Что нужно купить

**Сервер в Казахстане.** Не из экономии, а по двум причинам сразу: статья 12
Закона РК «О персональных данных и их защите» требует хранить базу с данными
граждан на территории страны, а правила домена `.kz` требуют указать при
регистрации оборудование в РК. Вы храните имена и телефоны гостей — это
персональные данные.

| Что | Сколько |
|---|---|
| Процессор | 2 ядра |
| Память | 4 ГБ |
| Диск | 40 ГБ SSD |
| Система | **Ubuntu 24.04 LTS**, чистая, без панелей управления |
| Сеть | публичный IPv4, порты 80 и 443 открыты |

Порт 80 обязателен, даже если всё работает по HTTPS: через него проходит
проверка при выпуске сертификата.

**Домен.** Один на всю сеть, клубы разводятся поддоменами: `cyberfox.kz`, а
залы на `club.cyberfox.kz` и `south.cyberfox.kz`. Платите один раз.

Для `.kz` нужен ИИН и резидентство, проверка документов занимает 1–3 дня.
`.com` оформляется за пять минут без документов.

## 2. Привязать домен к серверу

В панели регистратора: DNS → добавить запись **A**, имя `club`, значение — IP
сервера, TTL 300.

Проверить с любого компьютера:

```
ping club.вашдомен.kz
```

Должен отвечать IP вашего сервера. Обычно 5–30 минут. Пока не отвечает,
установку запускать бессмысленно — сертификат не выпустится.

**Короткий домен (необязательно).** Если хотите давать в рекламе короткий
адрес `cyberfox.kz` вместо `club.cyberfox.kz`, добавьте для него такую же
A-запись на тот же IP, а в `.env` впишите:

```
CYBERFOX_REDIRECT_DOMAIN=cyberfox.kz www.cyberfox.kz
```

Caddy получит на короткий домен сертификат и будет перенаправлять его на
основной. Несколько адресов — через пробел. Без этой строки короткий домен
просто не работает, основной от этого не страдает.

## 3. Ключ развёртывания

Репозиторий приватный, и сервер читает его **ключом только на чтение** —
отдельным от ваших личных ключей. Потеряется сервер — отзывается он один, и
больше ничего.

На сервере, под root:

```sh
ssh-keygen -t ed25519 -f /root/.ssh/cyberfox_deploy -N "" -C "cyberfox-server"
cat /root/.ssh/cyberfox_deploy.pub
```

Напечатанную строку добавить в GitHub: репозиторий → **Settings → Deploy keys
→ Add deploy key**. Галочку **«Allow write access» не ставить** — серверу
нужно только читать.

## 4. Забрать код и поставить

```sh
GIT_SSH_COMMAND="ssh -i /root/.ssh/cyberfox_deploy" \
  git clone --branch claude/computer-club-software-56dxgx \
  git@github.com:aliaskarov007/cyber-Fox.git /opt/cyber-fox

sudo /opt/cyber-fox/deploy/install.sh club.вашдомен.kz
```

Скрипт ставит Docker, сам придумывает пароль базы и секрет входа, проверяет
домен, поднимает базу, сервер, кассу с HTTPS и ежедневный бэкап — и ждёт, пока
касса откроется. Первый раз это 5–10 минут.

Если код ещё не забран, скрипт заберёт его сам — но тогда ключ он тоже заведёт
сам:

```sh
sudo bash install.sh --deploy-key   # напечатает ключ для GitHub
sudo bash install.sh club.вашдомен.kz
```

## 5. Что дальше

Открыть `https://club.вашдомен.kz` → «Зарегистрировать клуб». Дальше как
обычно: зоны, машины, тарифы, агенты — [setup.md](setup.md), разделы 4 и
дальше.

**Сохраните `/opt/cyber-fox/.env`.** В нём пароль базы и секрет входа, которые
скрипт придумал сам. Без этого файла база не откроется, а смена `JWT_SECRET`
выкинет из кассы всех сотрудников.

## 6. Обновления

Та же команда:

```sh
sudo /opt/cyber-fox/deploy/install.sh club.вашдомен.kz
```

Пароли в `.env` при этом не меняются, код обновляется. Обновляйтесь между
сменами: сервер перезапускается, и идущие сессии на минуту теряют связь.

## 7. Бэкап наружу

Копии базы делаются каждую ночь сами, но лежат на этой же машине. Её потеря
унесёт и базу, и копии — то есть балансы всех гостей. Поэтому копию надо
увозить.

```sh
sudo /opt/cyber-fox/deploy/backup-offsite.sh keys
```

Скрипт заведёт два ключа и напечатает, что куда вписать:

| Ключ | Где живёт | Зачем |
|---|---|---|
| **age**, закрытая половина | **в менеджере паролей, вне сервера** | расшифровать копию |
| **age**, открытая половина | в `.env` | зашифровать копию |
| **ssh** | на сервере | попасть в хранилище |

Копия шифруется **до** отправки, поэтому хранилище держит у себя то, что без
закрытого ключа не прочитать. Это не формальность: в дампе имена гостей,
телефоны и остатки на счетах.

**Закрытый ключ age печатается один раз и на диске не остаётся.** Потеряете —
копии превратятся в мусор, который не вскроет никто, включая нас. Держите его
там же, где пароль от сервера, и ни в коем случае не только на самом сервере:
смысл в том, чтобы он пережил машину.

Заполнив `.env`, проверьте сразу, не дожидаясь ночи:

```sh
sudo /opt/cyber-fox/deploy/backup-offsite.sh test
```

Копия делается и отправляется прямо сейчас, а в конце написано, уехала она или
нет. Без этой проверки о неработающей отправке вы узнали бы через сутки — или
в день аварии.

Папку в хранилище создайте заранее: `rsync` её не заводит.

## 8. Забытый пароль и платформенный вход

Две операции, которые делаются только на сервере: в кассе таких экранов нет и
быть не должно — она принадлежит клубу.

**Сотрудник забыл пароль.** Без почты скрипт покажет, кому можно сбросить:

```sh
sudo /opt/cyber-fox/deploy/reset-password.sh
sudo /opt/cyber-fox/deploy/reset-password.sh owner@club.kz
```

Новый пароль печатается один раз. Прежние входы этого сотрудника отменяются:
сбрасывают пароль обычно именно для этого.

**Вход для того, кто продаёт систему**, а не работает в зале:

```sh
sudo /opt/cyber-fox/deploy/platform-admin.sh me@example.com
```

Открывает `https://<домен>/platform` — список всех сетей с тарифами, числом
машин, гостей и последней активностью.

Это **не мастер-ключ в кассу клуба**: войти под владельцем через него нельзя.
Иначе достаточно было бы завести себе платформенную учётку, чтобы
хозяйничать в чужом зале.

## 9. Если не получилось

| Что видно | В чём дело |
|---|---|
| «GitHub не пустил» | Ключ не добавлен в Deploy keys или добавлен в другой репозиторий |
| «Домен указывает на никуда» | A-запись ещё не разошлась — подождать и повторить |
| «Домен указывает на другой IP» | A-запись ведёт не на этот сервер |
| Касса не ответила за 5 минут | `cd /opt/cyber-fox && docker compose logs --tail 50 server web` |
| Сборка падает молча | Не хватило памяти; скрипт добавляет 2 ГБ подкачки сам, но проверьте `free -h` |

Повторный запуск скрипта безопасен в любой момент: он не трогает пароли и не
стирает базу.
