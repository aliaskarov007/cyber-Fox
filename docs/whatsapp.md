# WhatsApp, подтверждение номера и ивенты

Гость общий для всей сети: один номер — один аккаунт во всех залах. Этим и
пользуемся: о турнире в одном филиале узнают гости всех филиалов. Пишем в
WhatsApp, потому что у нас им пользуется почти каждый, а Telegram — нет.

## Подключение номера (владелец сети)

Отправка идёт через [Green-API](https://green-api.com): сервис держит
WhatsApp-сессию телефона клуба и даёт к ней HTTP-доступ.

1. Заведите инстанс в кабинете Green-API.
2. Отсканируйте QR-код инстанса телефоном, номер которого будет писать гостям.
   Лучше отдельная SIM-карта: личный номер за рассылки могут ограничить.
3. В кассе: **Настройки → WhatsApp**. Перенесите `idInstance`, `apiTokenInstance`
   и, если кабинет показывает свой адрес API (`https://7103.api.greenapi.com`),
   его тоже.
4. «Подключить». Сервер сразу спрашивает у Green-API состояние инстанса:
   неверный токен видно здесь, а не завтра по тишине в ответ на рассылку.
5. «Отправить проверку» на свой номер.

Номер один на сеть: ответ «иду» должен прийти туда же, откуда ушло приглашение.

### Ответы гостей

Чтобы ответы «1» и «2» доходили, Green-API должен достучаться до сервера.
При сохранении касса передаёт свой адрес, и сервер сам прописывает инстансу
`https://<домен кассы>/api/whatsapp/webhook` и секрет к нему. Работает, только
если касса открыта по публичному https-домену (обычная установка с
`CYBERFOX_DOMAIN`). В установке только для локальной сети рассылка и коды
работают, а ответы — нет; это видно предупреждением после сохранения.

Подлинность уведомления сервер проверяет по секрету, который прописал сам.
Чужие и неподписанные уведомления молча пропускаются.

## Регистрация гостя за игровым ПК

На экране блокировки — кнопка **«Я здесь впервые — регистрация»**.

1. Экран показывает QR-код: ссылка `wa.me` на номер клуба с готовым текстом
   «Регистрация в <клуб>: CF-7K2Q».
2. Гость наводит камеру, WhatsApp открывается с этим сообщением — остаётся
   нажать «Отправить». Без камеры можно написать код вручную: номер клуба и
   код показаны под QR.
3. Сообщение приходит через Green-API. Номер отправителя подставляет сам
   WhatsApp, подделать его нельзя — значит, номер подтверждён, и отдельный код
   в ответ не нужен.
4. Экран сам переходит дальше: гость вводит ник и дважды PIN. Аккаунт создан,
   гость сразу входит.

Почему так, а не «введите телефон, получите код»: гость не набирает номер на
клубной клавиатуре, а клуб не пишет первым незнакомым номерам — для WhatsApp
это главный признак спама.

- Код живёт 10 минут; на машине действует только последний выданный.
- Если аккаунт с этим номером уже есть, новый не заводится: экран говорит
  «С возвращением» и просит новый PIN. Это же — восстановление забытого PIN
  без похода к стойке: номер гость только что доказал.
- Номер клуба сервер узнаёт у Green-API сам при подключении (видно в
  настройках). Пока инстанс не привязан по QR, регистрация за ПК недоступна и
  экран отправляет гостя к администратору.
- Нужен публичный https-адрес сервера — тот же, что и для ответов на
  приглашения: сообщение гостя приходит именно туда.

QR рисует сам агент, без сторонних библиотек (`apps/agent/src/shared/qr.ts`).
Читаемость проверена декодером OpenCV на всех версиях кода 1–10.

## Подтверждение номера (на стойке)

Карточка гостя → **Номер телефона → Отправить код в WhatsApp**. Гость называет
четыре цифры, администратор вводит их.

- Код живёт 10 минут, на него 5 попыток, новый — не чаще раза в минуту.
- Хранится хешем, привязанным к гостю.
- Ошибка ввода возвращается ответом, а не исключением: запрос сотрудника идёт
  одной транзакцией, и исключение откатило бы счётчик попыток.

Зачем вообще подтверждать: номер на стойке вводят на слух и с опечатками.
Рассылка на непроверенные номера — это сообщения посторонним людям, жалобы и
в итоге блокировка номера клуба. Поэтому **приглашения получают только гости с
подтверждённым номером**.

## Ивенты

Вкладка **Ивенты**. Смотреть может любой сотрудник (на стойке нужен список
записавшихся), создавать и рассылать — владелец или управляющий.

- **Кого приглашать:** все гости сети или только те, кто играл в этом зале.
- Перед рассылкой касса показывает, сколько гостей получат приглашение и
  сколько пропустит рассылка из-за неподтверждённого номера.
- Приглашения уходят фоновой очередью по одному, с паузой 1,5 с: пачка
  одинаковых сообщений — верный способ получить блокировку. Перезапуск
  сервера очередь не теряет.
- Повторное нажатие («Дослать новым») не пишет тем, кто уже приглашён, —
  только тем, кто подтвердил номер после первой рассылки.
- Отмена ивента снимает неотправленные приглашения.

### Что отвечает гость

| Ответ | Что происходит |
|---|---|
| `1`, `да`, `иду`, `+` | Записан на последний полученный ивент, который ещё впереди |
| `2`, `нет`, `не приду`, `-` | Отмечен как «не сможет» |
| `СТОП` | Больше не получает приглашений |
| `СТАРТ` | Снова получает |

На каждый распознанный ответ гость получает короткое подтверждение. Всё прочее
(«а во сколько начало?») — обычная переписка: бот на неё не отвечает, её видит
человек в WhatsApp на телефоне клуба.

## Чего пока нет

- Нет напоминания за час до начала и рассылки об отмене записавшимся.
- Одна сеть — один номер; разные номера для разных залов не поддерживаются.
